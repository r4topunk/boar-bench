# BOAR bench

TL;DR: 60 public English questions with frozen frontier-model-plus-web reference answers, a pairwise judge (Claude Opus via Claude Code, both A/B orders), and scorers, so any team can measure its own offline or online research assistant against the same references. Context in one sentence: the bench was built to measure whether an offline Android research assistant can reach more than half the quality of internet plus a frontier model (poidh bounty #31).

## Quick start

```sh
pnpm i                                   # zod + tsx for the trace validator
# 1. run your app on bench/v0.1/questions.public.jsonl, write one trace per question (TRACE-FORMAT.md)
node harness/validate.mjs my.traces.jsonl                                                  # optional strict schema check
node harness/judge.mjs --traces my.traces.jsonl --out my.judgments.jsonl --bench bench/v0.1 --dry-run   # counts calls, no spend
node harness/judge.mjs --traces my.traces.jsonl --out my.judgments.jsonl --bench bench/v0.1             # needs Claude Code (`claude -p`) logged in
python3 metrics/floor_metrics.py --dir . --runs my --questions bench/v0.1/questions.public.jsonl --decline-ratio 0.306
python3 scorers/score.py --traces my.traces.jsonl --judgments my.judgments.jsonl --bench bench/v0.1 --json my.score.json
```

The judge needs only `itemId`, `answer.text` and `error: null` per row (judge-minimal trace). Expect about 114 judge calls for 57 judged items x 2 orders, roughly 9 s per call with Opus. A rate limit stops the run; rerunning resumes. The judge uses your own Claude Code subscription; nothing is sent anywhere else.

## The three scales

| Scale | What it is |
|---|---|
| Raw | mean 1-5 rubric score of your answers vs the reference, judged pairwise |
| Floor-adjusted | raw corrected for the rubric floor (declined or empty answers still score 1), via `metrics/floor_metrics.py` |
| Win / tie / loss | per item, which side the judge prefers, both orders agreeing or not |

Read floor-adjusted and win rate first; raw alone flatters weak systems. The judge is closed and not bit-reproducible; expect confidence intervals of about +/-0.04 to 0.06 at n = 57.

## Layout

| Path | What |
|---|---|
| `bench/v0.1/` | 60 public questions, gold, safety track, reference answers (`refs/`), dataset card, `SHA256SUMS.json` |
| `bench/v0.3/` | pre-registered plan (hashed), schema and validation scripts, no items; `work/` is for your local drafts |

| `tools/hooks/` | pre-commit guard that blocks held-out plaintext |

## Provenance of the reference answers

`bench/v0.1/refs/refs.jsonl` holds the frozen references: generated by Claude Opus with web search (WebSearch and WebFetch through Claude Code), prompt `prompts/reference.v1.md`, 2026-09-30 to 2026-10-02. Answers may quote their cited sources, which keep their own terms. Each row records model, CLI version, prompt sha, time stamps and sources; `refs/NOTE.md` explains the public re-issue (local-path field removed, answer texts byte-identical to the internal file). Hashes: `bench/v0.1/SHA256SUMS.json`, `bench/v0.1/refs/MANIFEST.json`, `bench/v0.3/plan/SHA256SUMS`.

## Known limits

One model family (Claude) both wrote the v0.1 references and judges; v0.1 is a development set; small n. 25 v0.1 items quote or paraphrase a named author's public posts as short quotations with links (flagged in `bench/v0.1/DATASET_CARD.md`).

Health, first-aid and safety content (v0.1 health and danger items, their gold answers, the safety track and the safety rules) is AI-reviewed, not clinically reviewed. Nothing in this repository is medical advice.
